# imapforward

Monitor an IMAP INBOX via IDLE and forward new messages to another destination.

Supported destinations:

- **IMAP** – Append messages to another IMAP mailbox
- **Gmail API** – Import messages via `messages.import` with push notification support

## Quick Start

```bash
# Generate a config template
python imapforward.py --init config.json

# Edit config.json with your server details, then run:
python imapforward.py config.json
```

## Gmail API Setup

To use the Gmail API destination, you need a `credentials.json` file from Google Cloud Console.

### 1. Create a Google Cloud project

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Click the project selector at the top and choose **New Project**
3. Enter a project name (e.g. `imapforward`) and click **Create**

### 2. Enable the Gmail API

1. Navigate to **APIs & Services** → **Enabled APIs & Services**
2. Click **+ ENABLE APIS AND SERVICES**
3. Search for **Gmail API** and click **Enable**

### 3. Configure the OAuth consent screen

1. Navigate to **APIs & Services** → **OAuth consent screen**
2. Select **External** as the user type and click **Create**
3. Fill in the required fields (App name, User support email, Developer contact email)
4. On the **Scopes** step, click **Add or remove scopes**
5. Search for `gmail.insert` and check `https://www.googleapis.com/auth/gmail.insert`
6. Save and continue through the remaining steps
7. Under **Test users**, click **Add users** and add your Gmail address
8. Make sure the publishing status is **Testing** (not Production)

### 4. Create OAuth client credentials

1. Navigate to **APIs & Services** → **Credentials**
2. Click **+ CREATE CREDENTIALS** → **OAuth client ID**
3. Application type: **Desktop app**
4. Enter a name (e.g. `imapforward`) and click **Create**
5. Click **Download JSON** on the confirmation dialog
6. Save the file as `credentials.json` in the same directory as `config.json`

The file should look like this:

```json
{"installed":{"client_id":"xxxx.apps.googleusercontent.com","client_secret":"...","redirect_uris":["http://localhost"],...}}
```

> **Note:** Make sure the top-level key is `"installed"`, not `"web"`.
> If you see `"web"`, you selected "Web application" instead of "Desktop app" — delete and recreate.

### 5. Authorize the application

```bash
python imapforward.py config.json --auth
```

This will print an authorization URL. Open it in a browser, sign in with your Google account, and grant access. After authorization, the browser will show a "site can't be reached" error — this is expected. Copy the entire URL from the address bar and paste it into the terminal.

A `token.json` file will be created. The token is automatically refreshed on expiry; you should not need to re-authorize unless you revoke access or change scopes.

### Token and credential lifetime

- **`credentials.json`** is your OAuth client identity. It does not expire and can be reused indefinitely unless you delete or regenerate the client in Google Cloud Console.

- **`token.json`** contains an access token (valid for ~1 hour) and a refresh token (used to obtain new access tokens). The script automatically refreshes the access token during normal operation and writes it back to `token.json` after each delivery.

- **Testing vs Production mode:** If your OAuth consent screen is in **Testing** mode with user type **External**, refresh tokens expire after **7 days**. This means you will need to re-run `--auth` weekly. For long-term unattended operation, either switch the consent screen to **Production** mode (personal-use apps with fewer than 100 users do not require Google's verification review), or if you are using Google Workspace, set the user type to **Internal** — internal apps are not subject to the 7-day expiration and do not require verification.

## Configuration

### config.json

Generated by `--init`. The `destination` section determines the delivery method.

#### Gmail API destination

```json
{
  "source": {
    "host": "imap.example.com",
    "port": 993,
    "ssl": true,
    "username": "user@example.com",
    "password": "password",
    "folder": "INBOX",
    "done_folder": "DONE",
    "done_retention_days": 365,
    "failed_folder": "FAILED"
  },
  "destination": {
    "type": "gmail_api",
    "credentials_file": "credentials.json",
    "token_file": "token.json",
    "never_mark_spam": true
  },
  "log_level": "INFO"
}
```

#### IMAP destination

```json
{
  "destination": {
    "type": "imap",
    "host": "imap.example.org",
    "port": 993,
    "ssl": true,
    "username": "user@example.org",
    "password": "password",
    "folder": "INBOX"
  }
}
```

> **Note on Gmail as an IMAP destination:**
> You can use `imap.gmail.com` as the destination to copy messages into Gmail via IMAP.
> If your Google account has 2-step verification enabled, you will need to generate an
> [app password](https://myaccount.google.com/apppasswords) and use it in place of your
> regular password. Be aware that messages added via IMAP APPEND do not trigger push
> notifications on Android or iOS — use the Gmail API destination if you need notifications.

### Source options

| Key | Description |
|---|---|
| `host`, `port`, `ssl` | IMAP server connection |
| `username`, `password` | Login credentials |
| `folder` | Folder to monitor (default: `INBOX`) |
| `done_folder` | Move forwarded messages here (empty string to disable) |
| `done_retention_days` | Delete messages in `done_folder` older than this many days (0 to disable) |
| `failed_folder` | Move messages that fail delivery here (empty string to disable) |

When `done_retention_days` is set to a positive value (e.g. `365`), the script periodically purges old messages from the `done_folder`. The purge runs at most once per day during IDLE timeout cycles. It searches for messages with an INTERNALDATE before the cutoff, marks them as deleted, and expunges them.

When `failed_folder` is set, messages that fail delivery (e.g. rejected by Gmail due to dangerous attachments like password-protected ZIP files) are moved there instead of remaining in the source INBOX. Without this setting, failed messages stay as UNSEEN and delivery is retried on every IDLE cycle. The folder is created automatically if it does not exist.

## Running as a systemd service

```bash
# Install the unit file
mkdir -p ~/.config/systemd/user/
cp imapforward.service ~/.config/systemd/user/

# Edit paths in the service file if needed, then:
systemctl --user daemon-reload
systemctl --user start imapforward
systemctl --user enable imapforward

# Keep the service running after SSH logout
loginctl enable-linger $USER

# View logs
journalctl --user -u imapforward -f
```
